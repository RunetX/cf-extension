# Происхождение и границы аудита

Новый репозиторий содержит самостоятельно написанные адаптеры, инструменты и
синтетический генератор. Исходники и история constructor/cf-unwrapper, корпоративные
корпуса и платформа не включаются. Форматные решения делегируются git dependency
cf-unwrapper v0.1.0; Cargo.lock фиксирует remote commit.

Внутри этой зависимости есть встроенные seed/templates и другие ресурсы:
[инвентаризация](https://github.com/RunetX/cf-unwrapper/blob/v0.1.0/docs/embedded-assets.md),
[аудит переноса](https://github.com/RunetX/cf-unwrapper/blob/v0.1.0/docs/extraction-audit.md).
Генератор вызывает библиотечные API, которые могут использовать эти встроенные ресурсы.
Технический аудит не устанавливает права распространения сторонних материалов.

`tools/audit.py` проверяет известные path/patch/resource-tree/machine-path patterns,
remote tag в lockfile; это ограниченный технический фильтр. Он не заменяет review
происхождения данных, полного дерева VSIX и прав на сторонние материалы.

## Локальные иконки

В VSIX включены только самостоятельно написанные fallback SVG из extension/media/tree.
Адаптер читает выбранные двоичные изображения ICU ResB v2 установленной 1С и PNG внутри
ZIP, не извлекает формы и не запускает платформу. SVG-обёртки оригинальных PNG формируются
только в globalStorage расширения на машине пользователя. Пакеты .res, PNG и этот кеш
не копируются в исходники или дистрибутив. Синтетические тесты создают свои ресурсы/PNG
и не зависят от установленной 1С. Форматы CF/XML продолжает читать только cf_unwrapper.

## Логотип Конструктора

`extension/media/logo-k.png` — предоставленный пользователем логотип из
`docs/img/brand/logo-k.png` исходного репозитория Constructor, скопированный без изменения байтов.
В карточке расширения используется исходный PNG; `extension/media/constructor.svg` —
монохромная векторная адаптация буквы «К» для Activity Bar VS Code. Это бренд проекта,
а не ресурс платформы 1С. Исходные файлы бренда родительского репозитория не изменялись.

## Подсветка BSL

`extension/syntaxes/bsl.tmLanguage.json` — собственная TextMate-грамматика, написанная
для этого продукта по публично известному синтаксису языка 1С:Предприятие: русские и
английские ключевые слова, комментарии, строки с удвоенными кавычками (многострочные
включительно), числа и директивы препроцессора. Платформенные HBK/RES-ресурсы и
синтакс-помощник не копируются и не требуются. Грамматика привязана к языку `bsl`,
который расширение назначает только своим виртуальным документам модулей;
произвольные локальные `.bsl`-файлы и чужие расширения не затрагиваются.

## Анализатор BSL

`crates/model-server/src/bsl/` — перенос собственного анализатора из исходников
проекта Constructor (`src/bsl/lex.rs`, `src/bsl/mod.rs`): та же кодировка текста,
синтаксические проверки и определение места компиляции (`Site`). Место компиляции
по роли модуля сопоставляется в `analysis.rs`. Что перенесено не было:
платформенно-зависимые части исходника (контекст HBK, автодополнение `complete.rs`,
проверка неопределённых имён без точки) — они требуют справочника платформы, который
в продукт не входит; без него проверка давала бы ложные срабатывания на глобальных
именах платформы. Проверка обращений к коллекциям метаданных (`Справочники.Имя` и
аналоги) реализована заново через общедоступную модель `cf_unwrapper::meta::Config`:
для известных коллекций имя объекта сверяется с открытой конфигурацией без учёта
регистра. Синтакс-помощник платформы и её ресурсы не копируются и не требуются.

## Подсказки и переходы BSL

`crates/model-server/src/bsl/nav.rs` — ядро подсказок из constructor
`src/bsl/complete.rs` (таблицы коллекций менеджеров RU/EN, разбор заголовков методов,
сбор локальных переменных, определение слова под курсором) с заменой адаптера:
вместо справочника платформы метаданные читает `cf_unwrapper::meta::Config` через
общедоступные группы/объекты/подчинённые/записи модулей. Члены типов из HBK
не переносились; вместо них — только доказуемые имена (объекты коллекций, реквизиты
и табличные части, экспортные методы общих модулей и менеджеров) плюс собственный
минимальный набор широко известных методов менеджеров и объектов (создать, найти,
выбрать, записать — RU/EN). Полный контекст глобальных имён платформы не заявляется;
неизвестные и динамические имена не проверяются и не подсказываются.
