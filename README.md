# Конструктор для VS Code

Самостоятельный навигатор метаданных 1С: расширение VS Code и Rust model-server.
Форматы читает [cf-unwrapper v0.1.0](https://github.com/RunetX/cf-unwrapper/tree/v0.1.0).

В Activity Bar откройте **Конструктор**, выберите CF, CFE, EPF или корневой XML.
Нативное дерево загружает детей по мере раскрытия. Выбор объекта открывает палитру
свойств. Введите значение и нажмите **Применить** рядом с полем: это меняет модель
в памяти. Значок **●** показывает несохранённые изменения. Команда **Сохранить**
записывает бинарный источник, **Сохранить как / XML** выбирает новое назначение.
При смене или закрытии грязной модели доступны сохранить, отбросить и отменить.

Поддержаны Name, Synonym, Comment конфигурации, справочника и вложенного реквизита,
а также Hierarchical справочника. Synonym редактирует русское значение, сохраняя
другие языки. Поддержанные scalar/string/bool/enum свойства используют соответствующие
контролы; сложные и недоступные по условиям свойства показаны только для чтения.
Ошибки ввода сохраняют текст в поле; устаревшая версия модели отклоняется сервером.

В панели доступны поиск имени/синонима без учёта регистра, контекстные **Найти ссылки
GUID** и **Состав объекта** (реквизиты, табличные части). Ссылки — вхождения GUID в
записях контейнера, не семантический поиск BSL и не список позиций в исходном коде.
Неотображаемые записи выводятся с собственным именем и без ложной палитры объекта.

XML экспорт разрешён только в новый или пустой каталог. Непустой каталог отклоняется
без изменения его файлов. Для открытого XML обычное сохранение требует явного
назначения: бинарный файл или новый XML-каталог. Неподдержанные библиотекой версии,
свойства и неполный экспорт возвращают ошибку. Синтетические тесты проверяют адаптер;
совместимость произвольных корпоративных конфигураций здесь не заявляется.

## Установка

Скачайте или соберите локальный VSIX для своей платформы. В VS Code выполните
**Extensions: Install from VSIX…**, выберите `cf-extension-win32-x64.vsix` (Windows x64)
или соответствующий Linux VSIX и откройте Конструктор. В VSIX уже включён сервер,
Rust пользователю не нужен. Работа с файлами требует доверия Workspace Trust.
Фоновые процессы запускаются без shell, в Windows скрыто. Внешних CDN нет.

## Разработка и проверка

Нужны Rust stable, Node.js 22 и Python 3. Команды из корня независимого репозитория;
соседние исходники и платформа 1С не требуются.

```
python tools/check.py
python tools/generate-fixture.py target/synthetic.cf
cargo test --locked -p model-server --test rpc
npm --prefix extension test
npm --prefix extension run test:host
python tools/package.py
```

В Linux Host запускается через `xvfb-run -a npm --prefix extension run test:host`.
Runner скачивает официальный VS Code 1.95.3 через test-electron; при необходимости
`VSCODE_EXECUTABLE_PATH` задаёт существующий исполняемый файл VS Code. Всегда
используются отдельные временные workspace/user-data/extensions, пользовательский
профиль не используется. Тест проверяет activation/open/tree/select/properties/
edit/dirty/revision/search/references/composition/save/reopen/XML через настоящий Host.
Обычный check выполняет audit, Rust fmt/check/tests, npm ci/compile и Node process tests.
CI Windows/Linux вызывает те же команды. Chrome не открывается.

Для разработки укажите `cfExtension.serverPath` на `target/debug/model-server[.exe]`
либо положите бинарник в `extension/bin/`. Упаковка собирает release-бинарник и VSIX
в `extension/dist/`. `--target` выбирает совместимую платформу VSIX; кросс-компиляция
не выполняется, несовпадающий target отклоняется. Упаковка ничего не публикует.

## Протокол и синтетика

JSON-RPC 2.0 по stdio с UTF-8 `Content-Length: N\r\n\r\n`, предел 16 MiB.
Stdout — только протокол, stderr — диагностика. Контракт в [protocol.md](docs/protocol.md).
Один сервер владеет Config, ревизией, dirty и файловой транзакцией. Правка проходит
в отдельной модели и заменяет живую только после проверки. Бинарная запись —
собственный уникальный sibling temp, flush/sync и атомарная замена файла.

Генератор `--generate-fixture destination.cf` строит собственный минимальный XML
Configuration с произвольными UUID, именем NavigatorSynthetic и выключенными
мобильными возможностями. XML-оболочку пишет `xml::w::W`, импорт — `xml::imp`,
Catalog Products и Attribute/TabularSection создаются через `edit::add`/`add_child`.
Форматные записи, seed, шаблоны и корпоративные корпуса сюда не копируются.
Генерация использует встроенные ресурсы зависимости; граница описана в
[provenance](docs/provenance.md). BSL, DAP, визуальные редакторы и операции с живой
базой остаются следующими поставками: [roadmap](docs/roadmap.md).
